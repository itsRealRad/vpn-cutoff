# vpn-cutoff

**English:** [README.md](README.md)

اتصال‌های **زنده‌ی** کاربران تمام‌شده‌ی پنل 3x-ui را قطع می‌کند — منقضی، تمام‌حجم، یا
غیرفعال — بدون این‌که هسته ری‌استارت شود.

## دو مشکلی که این ابزار حل می‌کند، به ترتیب

**۱. پنل روی تقریباً هر کاری، ایکس‌ری را ری‌استارت می‌کند.**

وقتی پنل 3x-ui را نصب می‌کنی، با ساختن کاربر یا اینباند جدید، ویرایش کاربر یا
اینباند، غیرفعال کردن اینباند یا کاربر، اتمام حجم یا منقضی شدن کاربر و… هسته‌ی
ایکس‌ری ری‌استارت می‌شود. تنظیم پیش‌فرض پنل
`restartXrayOnClientDisable=true` است.

هر بار که هرکدام از این کارها انجام شود، تمام کاربران آنلاین به مدت دو سه ثانیه
دیسکانکت و کاملاً قطع می‌شوند.

فرض کن هر بار رباتت یک اکانت تست ۱۰۰ مگی برای کسی می‌سازد که معلوم نیست مشتری
شود یا نه — همان ساخت، همه‌ی مشتریان تو را قطع می‌کند. همان اکانت تستی که زمان یا
حجمش تمام می‌شود، دوباره همه را قطع می‌کند. گیر کردن ویدیوی یوتیوب و اینستاگرام و
موقع استریم دیدن، لگ و پکت‌لاس و بافر در بازی، قطع لحظه‌ای تماس ویدیویی، کنفرانس،
تریدینگ و ضرر مالی — این‌ها می‌توانند بارها در روز برای مشتریانت اتفاق بیفتند و
باعث نارضایتی‌شان شوند.

پس از تنظیمات پنل، نمی‌گذاری ایکس‌ری ری‌استارت شود. هیچ‌چیز ری‌استارت نمی‌شود، همه
وصل می‌مانند.

**۲. حالا کاربر تمام‌شده اصلاً قطع نمی‌شود.**

پنل فقط کاربر تمام‌شده را از کانفیگ *در حال اجرا* حذف می‌کند. اتصال‌هایی که **از قبل
باز هستند** دست‌نخورده می‌مانند، پس کاربری که حجمش تمام شد تا وقتی کلاینتش خودش
اتصال دوباره برقرار کند، دارد از تونل استفاده می‌کند.

همین باگی است که موقع دوران قطعی اینترنت باعث می‌شد از یک اکانت تست ۱۰۰ مگی،
۱۰۰ گیگ حجم بکشند و میلیون‌ها تومان ضرر به صاحب پنل بزنند.

`vpn-cutoff` جواب مشکل دوم است. دیتابیس پنل را فقط-خواندنی می‌خواند، کاربرانی را
که *همین حالا* تمام‌شده‌اند پیدا می‌کند، و دقیقاً همان اتصال‌های زنده را قطع می‌کند —
بقیه وصل می‌مانند.

پس: ری‌استارت را خاموش کن، این را نصب کن، و هر دو خاصیت را با هم داری. نصب‌کننده
خودش آن کلید را خاموش می‌کند و در هر حالت گزارش می‌دهد.

## هر هسته چطور قطع می‌شود

سه نوع هسته پشتیبانی می‌شود، هرکدام با اهرمی که همان هسته واقعاً دارد:

| هسته / اینباند | روش قطع اتصال زنده |
|---|---|
| **ایکس‌ری** — اینباندهای TCP (VLESS، VMess، Trojan، Shadowsocks، xhttp/ws/tcp، پشت CDN یا مستقیم) | `ss -K` روی همان ۵-تاپل دقیق |
| **ایکس‌ری** — اینباندهای UDP/QUIC (Hysteria، TUIC، MASQUE) | بلاک `iptables` به‌ازای هر فلو، بر اساس پورت مبدأ کلاینت |
| **AmneziaWG** اینباندهای کرنلی | `awg set <iface> peer <pubkey> remove` |
| **WireGuard** اینباندهای کرنلی | `wg set <iface> peer <pubkey> remove` |

## چه می‌کند

هر ۲ ثانیه دیتابیس پنل را (فقط-خواندنی) می‌خواند و کاربرانی را که غیرفعال، منقضی یا
تمام‌حجم هستند پیدا می‌کند. برای هرکدام که هنوز آنلاین است، اتصال دقیقش را با اهرم
جدول بالا قطع می‌کند.

هیچ ری‌استارتی، هرگز. پروسه‌ی هسته دست نمی‌خورد.

## چه کاری عمداً نمی‌کند

این بخش از فهرست امکانات مهم‌تر است، چون ابزار اتصال می‌کشد:

- **هرگز ایکس‌ری را ری‌استارت نمی‌کند** — نه در نصب، نه در ارتقا، نه در قطع. تنها
  ری‌استارتی که نصب‌کننده می‌تواند راه بیندازد، همان ری‌استارت یک‌باره‌ی x-ui است که
  لاگ اکسس لازم دارد، و آن هم اختیاری است (`--with-accesslog`).
- **به دیتابیس پنل چیزی نمی‌نویسد، جز یک تنظیم** — همان
  `restartXrayOnClientDisable=false` خودش. بقیه‌ی کارها فقط-خواندنی باز می‌شود
  (`PRAGMA query_only=1`). هیچ کاربر، شمارنده‌ی ترافیک یا اینباندی تغییر نمی‌کند.
- **آی‌پی مشترک را هرگز نمی‌کشد** — اگر دو کاربر پشت یک آدرس باشند، مسیر جایگزین
  هر دو را رد می‌کند تا مشتری پولی قطع نشود. قطع به‌ازای هر کاربر (با لاگ اکسس) این
  محدودیت را کامل برمی‌دارد.
- **فقط قواعد خودش را دست می‌زند** — قواعد iptables کامنت `xui-cutoff` دارند؛
  `--uninstall` دقیقاً همان‌ها را برمی‌دارد و بس.
- **جای حدس زدن، متوقف می‌شود** — نبودن 3x-ui، پیش‌نیازی که نمی‌تواند نصب کند، یا
  شکست selftest، همه نصب را لغو می‌کنند بدون این‌که چیزی بالا بیاید.

## نصب

3x-ui باید از قبل نصب باشد و حداقل یک اینباند ساخته شده باشد. بقیه‌اش —
`python3`، `iproute2` (`ss -K`)، `iptables` — خودکار تشخیص داده و نصب می‌شود.
apt، dnf، yum، apk، pacman و zypper هر شش تا پشتیبانی می‌شوند.

**برای قطع دقیق به‌ازای هر کاربر، لاگ اکسس لازم است.** قبل از انتخاب حالت، بخش
[لاگ اکسس](#لاگ-اکسس-چرا-لازم-است) را بخوان.

```bash
curl -fsSL https://raw.githubusercontent.com/itsRealRad/vpn-cutoff/main/install-xui-cutoff.sh -o /tmp/i.sh
sudo bash /tmp/i.sh --with-accesslog
```

روی سرور تازه‌ای که پنل را دارد، همین تمامِ کار است.

اگر پنل نصب نباشد، نصب‌کننده می‌ایستد و می‌گوید:

```
  3x-ui is not installed on this host.
  Install the panel first, create one inbound, then re-run this installer.
```

سروری که systemd ندارد صریحاً رد می‌شود؛ جایگزینی برای init وجود ندارد.

یا فایل تک‌نفره را کپی کن و اجرا کن:

```bash
scp install-xui-cutoff.sh root@HOST:/root/
ssh root@HOST 'bash /root/install-xui-cutoff.sh --with-accesslog'
```

### حالت‌ها

| دستور | اثر |
|---|---|
| `install-xui-cutoff.sh --audit` | **از اینجا شروع کن.** گزارش می‌دهد همین حالا چه چیزی دارد نشت می‌کند. هیچ‌چیز را تغییر نمی‌دهد، هیچ‌چیز نصب نمی‌کند. |
| `install-xui-cutoff.sh` | نصب / ارتقا. به لاگ اکسس دست نمی‌زند. کلید ری‌استارت پنل را خاموش می‌کند. |
| `install-xui-cutoff.sh --with-accesslog` | نصب و روشن کردن لاگ اکسس. |
| `install-xui-cutoff.sh --accesslog-only` | فقط روشن کردن لاگ اکسس. |
| `install-xui-cutoff.sh --status` | نسخه، وضعیت سرویس، مسیر لاگ، قواعد خودش، پیش‌نیازهای غایب، کلید ری‌استارت. |
| `install-xui-cutoff.sh --uninstall` | حذف سرویس، فایل‌ها و **قواعد iptables خودش**. |

نصب‌کننده دیتابیس، کانفیگ، باینری اکس‌ری و پورت API را خودکار تشخیص می‌دهد، هر
پیش‌نیاز غایب سیستم‌عامل را نصب می‌کند، `restartXrayOnClientDisable` را خاموش
می‌کند، و کل نصب را به یک selftest داخلی گره می‌زند: اگر selftest رد شود، هیچ‌چیز
بالا نمی‌آید.

## نشت را قبل از نصب ببین

`--audit` دیتابیس پنل و لاگ اکسس را می‌خواند و چاپ می‌کند همین حالا روی این سرور چه
خبر است. نه می‌نویسد، نه می‌کشد، نه نصب می‌کند:

```
  vpn-cutoff audit  --  2026-10-31 20:52:26

  finished clients            : 23
     disabled                 : 3
     expired                  : 20
     over quota               : 0
  still connected RIGHT NOW   : 4 client(s), 6 live flow(s)
  quota overrun, measurable    : 12.40 GB   (~124,000 at 10,000/GB)

  email                        reason          used      limit  flows
  trial-8f21                   quota          12.51G      0.10G      2
  ali-01                       expired        84.20G   unlimited      1
  ...

  Per-user cutting is available (access log is on).
```

دو نکته‌ی صداقتی، چون عدد ساختگی از نبود عدد بدتر است:

- **تمام‌حجم** دقیق است — همان `مصرف − سقف`، مستقیم از دیتابیس.
- **منقضی / غیرفعال** فقط *مصرف* را نشان می‌دهد. نمی‌توانیم بدانیم چه مقدارش بعد از
  مهلت بوده، پس به‌عنوان «نشت» شمرده نمی‌شود.

قیمت هر گیگابایت را در `/etc/xui-user-cutoff.conf` بگذار
(`PRICE_PER_GB=10000`) تا خط گزارش پول شود. مقدار `0` آن خط را پنهان می‌کند.

## لاگ اکسس (چرا لازم است)

بدون لاگ، ابزار فقط می‌تواند بر اساس **آدرس آی‌پی** عمل کند: اگر دو کاربر یک آدرس
داشته باشند (NAT، CGNAT، لبه‌ی CDN) باید هر دو را رد کند، چون قطع آدرس، کاربر سالم
را هم قطع می‌کند.

با لاگ اکسس، هر اتصال پذیرفته‌شده با آدرس واقعی مبدأ کلاینت، پورت مبدأ **و** ایمیل
ثبت می‌شود:

```
from 198.51.100.24:41872 accepted tcp:... [in-example-udp >> direct] email: alice
```

آن `ip:port` دقیقاً یک فلوی کرنل را مشخص می‌کند، پس یک کاربر قطع می‌شود و کاربری
دیگر روی همان آدرس دست‌نخورده می‌ماند.

روشن کردن لاگ هر دو جا را عوض می‌کند — تمپلیت دیتابیس و فایل زنده‌ی `config.json` —
و بعد `xray api restartlogger` را صدا می‌زند. پروسه ری‌استارت نمی‌شود.

## پیش‌نیازها

- 3x-ui با ایکس‌ری
- لینوکس با `CONFIG_INET_DIAG_DESTROY=y` (پشتیبانی `ss -K`) و `iptables`
- `python3` (نسخه ۳.۶ یا بالاتر)، بدون هیچ پکیج بیرونی
- systemd

## محدودیت‌های شناخته‌شده

- پروتکل‌های مبتنی بر QUIC را نمی‌شود فوری از سطح کرنل قطع کرد. QUIC بسته‌های ICMP
  را نادیده می‌گیرد و سوکت UDP خودش را `connect()` نمی‌کند، پس کلاینت فقط وقتی
  متوجه می‌شود که timeout بیکاری خودش برسد. TCP فوری قطع می‌شود.
- قطع به‌ازای هر کاربر به لاگ اکسس نیاز دارد. بدون آن، آدرس‌های مشترک رد می‌شوند.
- هر ۲ ثانیه یک کوئری فقط-خواندنی SQLite. هزینه‌ی CPU و RAM ناچیز است؛ زیرفرایندها
  (`xray api`، `ss`، `awg`) فقط وقتی اجرا می‌شوند که چیزی واقعاً عوض شده باشد.
